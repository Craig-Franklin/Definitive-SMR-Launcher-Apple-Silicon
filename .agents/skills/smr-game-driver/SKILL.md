# Finite AI game testing

Read [AI_GAME_TESTING.md](../../../docs/AI_GAME_TESTING.md) for the supported
command, scene loop and acceptance criteria. Private current authority starts at
the owner's `.handoff/START_HERE.md`; it supplies the current Run, source closure,
queue/start helper and return-state evidence. A skill invocation does not resume
a pause or supply missing runtime admission.

Before launch, verify actual native provenance and the existing owner. Use the
supported process/queue checks. An unowned game belongs to Craig: do not send it
input, stop it or switch its profile. If busy, continue independent source/docs.
After personal play, preserve the current profile, saves and preferences as the
return state. Reuse unchanged source baselines; do not restore a pre-play state.

Use the existing one-use admission and maintained `LauncherApplication.play`
route. Finish source/knowledge reads before the finite interval. Compose the
existing reply, next-request read and image display in one host call per scene.
Inspect each fresh rendered scene before choosing input; do not replay pending
or ended requests. The controller handles unique semantic AX Play locally.

For rail construction, identify the actual endpoint and its direction in the
current image. Start with a short straight extension onto nearby clear ground.
Reject a red invalid preview immediately; shorten or change direction using a
fresh image. Purple preview is not a committed rail. Confirm visible new rail
and reduced funds before advancing. After exact reopen, extend the saved segment
briefly in its visible direction. Long terrain searches previously consumed the
time needed for final quit.

Keep the original 480-second action and 900-second cleanup bounds. Request normal
quit once, then recognize the actual current menu/confirmation. Require exact
normal-exit evidence, independent restoration/preservation readback and lease
settlement. Count a full cycle only after gameplay, exact unique save/reopen,
continued construction, both normal exits and restoration have been observed.
Retain failed/UNKNOWN history. A retry needs a changed hypothesis and fresh job.

For source regression checks, use Python 3.12 and the focused commands in the
guide. Those checks cannot establish live gameplay or repeatability. Record the
actual result and next step in the existing compact handoff.
