# Individual stop-only support

Experimental support for one coordinator-owned, individually admitted game test. The helper consumes a root-supplied exact process identity and completed observation receipts. It stops that incarnation on an observation lease of 60 seconds or the original anchor plus 540 seconds. It cannot launch a game, click, save, restore profiles, retry or run batches.

This isolated bundle preserves the reviewed component and Observer bytes. `pins.json` binds the fixed dependency set. The host entry point adds the actual interpreter/clock handshake; `consumer.py` is the pure root-side check for current helper identity, matching state and bound receipts, independent game/watchdog observations, completed monitoring and phase. The root must also perform the existing preservation, ownership, capacity, provider and code-freeze checks before every action. A receipt alone grants no GUI, restoration or next-job authority.

Run the fake-only checks from the repository root:

```sh
.venv/bin/python -B scripts/research/individual_stop_support/check.py
```

The checker makes a separate current-owner private0700 copy before importing the bundle. It never imports the actual macOS adapter or invokes a game. Ordinary checkout directories are not suitable live input packets. Actual use requires a separately prepared private0700 code directory and packet, a root-created admission record and the exact reviewed operating assurance in issues #1 and #127. `host.py` is stop-only; root alone supplies the manual launch, descriptor and observations.

The operational adapter freshly compares PID, birth and executable before each signal and refuses observed mismatches or errors. Separate inspection and signaling do not prove kernel-atomic protection; a replacement during that interval could receive a signal. The manual launch-to-binding interval is also uncovered. Those residual limitations require the explicit reviewed assurance decision. Scheduling deadlines are operational targets, and overruns remain failures. All original maps, scenarios, features, settings and current/future saves remain protected.

The source and synthetic checks establish only their stated bounded behavior. Actual individual integration does not establish full gameplay, cargo delivery, numerical save persistence or scenario acceptance. Production batch/recovery and expanded bootstrap remain closed under the operating contract.
